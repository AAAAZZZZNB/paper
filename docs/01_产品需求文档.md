# 道路管理系统产品需求文档（PRD）

- **文档版本**：V0.1
- **编制日期**：2026-10-06
- **产品名称**：交通风险智能道路管理系统
- **产品定位**：面向道路管理人员的风险识别、知识分析、事件研判与处置辅助平台
- **关联研究**：基于论文中的事故 SHAP 分析、轨迹冲突极值模型、风险知识图谱、案例知识库和知识增强 LLM Agent

---

## 1. 背景与问题定义

### 1.1 现状问题

当前道路安全管理通常存在以下问题：

1. 历史事故数据、车辆轨迹数据、道路环境数据相互分散，难以形成统一风险画像。
2. 事故模型能给出特征重要性，但分析结果多停留在论文图表或离线文件中，不能直接服务于道路管理。
3. 轨迹冲突模型能识别极端风险，但阈值、场景和处置措施之间缺乏可解释关联。
4. 事故报告、处置经验和交通规范通常以自然语言或人工文档保存，检索和复用成本高。
5. 大语言模型可以生成流畅文本，但如果缺少图谱、规则和案例约束，可能产生未被证据支持的事故事实或处置建议。
6. 现有分析常常缺少事件工单、人工审核、处置反馈和模型迭代，不能形成“识别—处置—复盘—学习”闭环。

### 1.2 产品机会

将论文研究成果工程化，形成一个具备以下特征的系统：

> 多源数据接入 → 风险模型分析 → 结构化风险知识 → 图谱与案例检索 → 规则兜底 → LLM 研判 → 人工审核 → 处置闭环 → 反馈学习

## 2. 产品目标与边界

### 2.1 产品目标

#### 近期目标（MVP）

- 支持事故数据上传、字段校验、训练任务和 SHAP 可视化。
- 支持轨迹数据上传、冲突指标计算、POT/GEV/GPD 模型分析和阈值展示。
- 支持风险知识条目导入、实体关系查询、子图展示和证据溯源。
- 支持输入危险场景或事故事件，生成风险等级、风险成因、相似案例和处置建议。
- 支持事故报告草案导出，并进入人工审核状态。

#### 中期目标

- 支持道路地图上的风险热区、时段风险和路段对比。
- 支持实时或准实时轨迹流接入和超阈值告警。
- 支持事件工单、处置状态、责任部门、反馈结果和复盘记录。
- 支持模型、知识、阈值和提示词的版本管理及离线评估。

#### 长期目标

- 支持多路段、多区域、多数据源的统一风险运营。
- 支持多模态证据接入（图片、视频、气象图等），但必须通过人工核验和证据边界控制。
- 支持风险干预措施的效果评估，为限速、匝道控制、警示发布和设施优化提供依据。

### 2.2 非目标与使用边界

- 不替代交警或道路管理部门的正式事故调查和责任认定。
- 不直接自动执行限速、封道、车辆控制等高风险操作；此类动作必须经过授权人员确认。
- 不把历史案例中的事故原因直接迁移为当前事故事实。
- 不将语言模型的自然语言流畅性作为风险结论的唯一依据。
- 不在未获得授权的情况下处理可识别的车牌、人脸、驾驶员身份等敏感信息。

## 3. 目标用户与角色权限

| 角色 | 主要任务 | 核心权限 |
|---|---|---|
| 道路管理员 | 查看路段风险、处理告警、维护道路场景 | 风险地图、告警、事件工单、处置反馈 |
| 交通安全分析师 | 分析事故和轨迹数据、训练模型 | 数据集、SHAP、EVT、模型评估 |
| 应急处置人员 | 研判当前事件、执行和记录处置 | 事件详情、方案推荐、工单更新、报告草案 |
| 知识管理员 | 维护实体、关系、案例和规则 | 知识图谱、案例库、阈值规则、审核发布 |
| 专家/审核员 | 审核风险结论和事故报告 | 证据审阅、修改、批准、驳回 |
| 系统管理员 | 维护用户、权限、日志和配置 | 用户、角色、系统配置、审计 |
| 研究人员 | 复现实验、比较模型、导出结果 | 数据脱敏、实验任务、指标和图表导出 |

权限建议采用“角色 + 数据范围 + 操作范围”三层控制：例如某分析师可以查看广州环城高速某些路段的数据，但不能发布全局阈值规则。

## 5. 核心业务流程

### 5.1 离线风险知识生产流程

```text
事故/轨迹/道路/天气数据
        ↓
数据质量检查与脱敏
        ↓
特征工程与模型训练
        ├─ XGBoost + SHAP
        └─ TDTC/MTTC/PET/ΔV + POT/EVT
        ↓
结构化提取因素、影响方向、阈值、风险等级
        ↓
实体对齐、知识审核、版本发布
        ↓
风险知识图谱 + 案例知识库
```

### 5.2 在线风险研判流程

```text
人工录入/接口事件/轨迹告警
        ↓
事件解析：地点、时间、天气、道路、车辆、指标
        ↓
独立阈值规则判定（风险底线）
        ↓
知识图谱子图检索 + 历史案例检索
        ↓
提示词组装与证据清单生成
        ↓
LLM 输出结构化风险报告和处置建议
        ↓
一致性校验、事实边界检查、人工审核
        ↓
发布工单/报告草案/告警闭环
        ↓
处置反馈与复盘入库
```

## 6. 功能需求

### F0. 首页风险驾驶舱（补充功能）

**目的**：让管理人员进入系统后首先看到“哪里有风险、风险为什么存在、需要谁处理、处理到哪一步”。

**功能要求**：

- 展示当前高风险事件数、待审核报告数、超阈值路段数和模型运行状态。
- 展示风险地图、风险趋势、风险来源构成（事故侧/冲突侧/环境侧）。
- 支持按区域、道路、时间、风险等级和事件状态筛选。
- 每张指标卡片可以下钻到具体事件、路段或模型结果。

**验收标准**：从首页点击任一高风险指标，3 次操作内可以打开对应事件详情或证据页面。

---

### F1. 事故数据 SHAP 分析

**目的**：将历史事故数据中的严重程度影响因素转化为可解释的分析结果和风险知识。

#### 输入

- 事故记录：时间、道路、方向、里程、道路类型、天气、能见度、温度、风力风向、车辆类型、事故类型、伤亡/损失等。
- 训练配置：目标变量、特征列、训练集/验证集划分、样本平衡方法、随机种子、模型参数。

#### 功能

1. 数据集上传、字段映射、缺失值和异常值检查。
2. 支持分类/回归任务配置，默认面向事故严重程度分类。
3. 支持 XGBoost 训练、交叉验证和模型版本保存。
4. 生成全局特征重要性、SHAP beeswarm、bar、dependence、waterfall 图。
5. 支持按天气、时段、道路类型、车辆类型、事故类型分组比较。
6. 支持输入单条事故记录，生成局部风险解释。
7. 识别“风险因素—影响方向—目标结果”的结构化知识候选。
8. 支持将经审核的 SHAP 结果发布到风险知识图谱。
9. 支持图表、数据表和分析结论导出。

#### 输出

- 模型指标：Accuracy、F1、Macro-F1、AUC、混淆矩阵等。
- 特征影响：mean(|SHAP|)、影响方向、分位数、分组差异。
- 可解释图：全局图、局部图、分组图。
- 知识候选：因素、目标、影响关系、重要性、适用场景、来源版本。

#### 约束

- SHAP 重要性不等同于因果效应，界面必须显示“模型解释，不代表因果结论”。
- 因为数据泄漏、结果变量或处置变量导致的字段不得直接作为风险因素发布。
- 低样本分组需显示样本量和置信提示。

#### 验收标准

- 能完成一份合法数据集的训练、解释、保存和复现。
- 每一条发布的知识都能回溯到数据集版本、模型版本和 SHAP 分析任务。
- 图表支持 PNG/SVG 下载，表格支持 CSV/XLSX 下载。

---

### F2. 轨迹数据极值模型分析

**目的**：从车辆微观交互行为中识别潜在冲突和极端风险，形成可用于监测和告警的阈值规则。

#### 输入

- 轨迹数据：车辆 ID、时间戳、位置、车道、速度、加速度、航向、车辆类型等。
- 道路拓扑：路段、车道、方向、上下游关系、限速、匝道、长下坡、弯道等。
- 环境数据：天气、降雨、能见度、光照、节假日、交通流状态等。

#### 功能

1. 轨迹文件上传、时间戳统一、车辆 ID 校验和坐标转换。
2. 异常值识别、缺失点处理、轨迹平滑和车辆交互关系识别。
3. 计算 TDTC、MTTC、PET、ΔV、时距、速度差、加速度等冲突指标。
4. 支持阈值分位数、经验阈值和 POT 超阈值样本提取。
5. 支持 GPD/GEV 极值模型拟合、参数估计和置信区间。
6. 支持平稳与非平稳模型对比，分析天气、时段、流量、道路场景等协变量影响。
7. 输出重现水平、超越概率、风险等级阈值和阈值稳定性。
8. 支持冲突点地图、时间趋势图、指标分布图、QQ 图和重现水平图。
9. 将“指标—阈值—风险等级—适用场景”发布为规则和图谱知识。

#### 默认风险规则示例

> 具体数值必须由数据分析任务发布，以下仅为产品示例，不是最终业务阈值。

| 指标 | 示例判定 | 系统行为 |
|---|---|---|
| TDTC | 小于高风险阈值 | 触发高风险冲突告警 |
| MTTC | 小于高风险阈值 | 提升事件优先级 |
| PET | 小于阈值 | 标记交叉/合流冲突 |
| ΔV | 大于阈值 | 提升潜在严重程度关注等级 |

#### 约束

- 每条阈值必须携带模型版本、样本范围、适用路段、时间范围和置信信息。
- 不同指标方向必须统一：数值越小越危险或越大越危险，不能依赖自然语言解释。
- 数据质量不足、样本量不足或模型拟合不稳定时不得自动发布阈值。

#### 验收标准

- 给定同一数据版本和随机种子，模型结果可复现。
- 能查看阈值的统计依据、适用场景和发布状态。
- 越过高风险阈值的事件能被告警模块正确接收。

### F3. 交通风险知识图谱分析

**目的**：将事故风险、冲突风险、道路场景、历史案例和处置措施组织为可查询、可解释、可审计的统一知识体系。

#### 核心实体

- `RoadSection`：道路、方向、里程、车道、匝道、长下坡、弯道等。
- `RiskFactor`：暴雨、夜间、货车、速度差、拥堵等。
- `AccidentType`：追尾、侧翻、碰撞、人员伤害等。
- `ConflictIndicator`：TDTC、MTTC、PET、ΔV 等。
- `RiskLevel`：低、中、高、极高。
- `KnowledgeRule`：SHAP 关系、EVT 阈值、约束规则。
- `AccidentCase`：历史事故案例页面。
- `Countermeasure`：限速、警示、分流、现场防护、清障、救援等。
- `Evidence`：数据集、模型、报告、人工审核记录和来源链接。

#### 核心关系

- `occurs_on`：事件发生于道路场景。
- `increases_risk`：因素增加风险。
- `associated_with`：因素与事故/冲突相关。
- `has_indicator`：场景具有冲突指标。
- `exceeds`：指标超过阈值。
- `has_risk_level`：事件或场景对应风险等级。
- `similar_to`：案例之间相似。
- `mitigated_by`：风险可由措施缓解。
- `supported_by`：结论由证据支持。
- `reviewed_by`：知识由专家审核。

#### 功能

1. 图谱总览：实体、关系、来源和版本统计。
2. 场景查询：输入“暴雨 + 夜间 + 长下坡 + TDTC”返回局部子图。
3. 多跳推理：风险因素 → 风险等级 → 处置措施 → 相似案例。
4. 证据面板：显示 SHAP 数值、EVT 阈值、样本范围、模型版本和审核状态。
5. 实体对齐：统一“暴雨/大雨/强降雨”等同义词，维护规范名称。
6. 案例维基：按标签、道路、天气、时段、事故类型检索历史案例。
7. 知识审核：草稿、待审核、已发布、已废弃四种状态。
8. 图谱与案例相互跳转。

#### 验收标准

- 一条已发布知识可以查看来源、审核人和版本。
- 图谱查询结果可转化为 LLM 可读的证据文本。
- 删除或废弃知识后，后续新生成报告不能继续引用该知识。

### F4. 基于大语言模型的风险分析与事故处理方案推荐

**目的**：把多源数据和知识检索结果转化为结构化、可解释、可审核的风险研判和处置方案。

#### 事件输入方式

- 人工填写事件表单。
- 导入结构化事故记录。
- 接收轨迹冲突告警。
- 粘贴现场描述或值班记录。
- 上传图片作为“待核验证据资产”；默认不直接从图片推断事实。

#### Agent 工具链

1. **事件解析器**：识别道路、时间、天气、场景、车辆、事故类型和指标。
2. **规则引擎**：独立执行阈值判定，作为风险等级底线。
3. **图谱检索工具**：获取相关因素、关系、阈值、措施和证据。
4. **案例检索工具**：按规范标签召回历史案例，并返回原因/处置段落。
5. **一致性校验器**：检查风险等级是否低于规则等级、事实是否越界、引用是否存在。
6. **报告生成器**：按照固定模板生成风险评估和事故报告草案。
7. **方案排序器**：按风险等级、场景、资源、时效和可执行性排序推荐措施。

#### 统一输出结构

1. 事件摘要
2. 风险等级
3. 风险指数或风险区间
4. 风险成因与关键影响因素
5. 冲突指标与阈值判定
6. 知识图谱证据
7. 相似历史案例
8. 建议处置方案
9. 建议优先级、责任角色和时限
10. 待核验信息
11. 证据来源与版本
12. 自动生成时间和审核状态

#### 处置方案推荐分层

| 层级 | 典型措施 | 是否允许自动发布 |
|---|---|---|
| P0 紧急 | 现场防护、二次事故预警、救援联动、封闭/分流建议 | 不允许，需授权确认 |
| P1 高优先 | 限速建议、可变情报板、巡检加密、清障调度 | 需人工确认 |
| P2 常规 | 路段复盘、设施检查、标志标线优化、驾驶提示 | 可进入待办任务 |
| P3 长期 | 工程改造、照明/排水/防护设施优化、运营策略评估 | 进入规划评审 |

#### 事实安全约束

- 事故事实只能来自结构化输入、已审核证据或人工补充。
- 历史案例只能作为“参考案例”，不能改写为当前事故已经发生的事实。
- 未知字段必须输出“待核验/未知”。
- LLM 不能修改独立规则引擎判定的最低风险等级。
- 任何建议都必须标注“知识来源/规则来源/案例参考/模型推断”之一。
- 系统输出为“辅助研判与报告草案”，必须有人工审核状态。

#### 验收标准

- 输入一个危险场景后，系统能够返回固定结构的风险报告。
- 报告中每条关键结论至少关联一个证据来源或明确标注为推断。
- 规则判定为高风险时，LLM 输出不得出现低风险等级。
- 可将报告保存、审核、修改、发布和导出。

---

### F5. 事件中心与事故处置闭环（补充功能）

**目的**：把分析结果转化为可执行的管理任务，而不是只生成一段文字。

#### 功能

- 事件自动建档：来源、时间、位置、发现方式、风险等级、当前状态。
- 状态流转：新建 → 研判中 → 待处置 → 处置中 → 待复核 → 已关闭。
- 责任分派：部门、人员、班组、值班角色和截止时间。
- 处置清单：措施、优先级、执行人、执行时间、完成证据和备注。
- 升级机制：超时未处理、风险升级、二次冲突或信息缺失时升级。
- 复盘记录：实际影响、措施效果、误报/漏报原因、知识更新建议。
- 形成“告警—工单—报告—复盘”完整链路。

---

### F6. 风险地图与告警中心（补充功能）

**目的**：提供道路管理视角下的空间化风险监测。

#### 功能

- 路段风险热力图、冲突点分布图和事故点图层。
- 按小时、日、周、月份查看风险趋势。
- 展示道路、天气、流量、事故和冲突指标的叠加关系。
- 支持静态离线分析和准实时数据刷新。
- 告警策略可按指标、阈值、持续时间、空间范围和时间段配置。
- 告警去重、合并、抑制和恢复，避免同一事件重复轰炸。
- 风险变化检测：同一路段风险相较历史基线显著上升时提醒。

---

### F7. 事故报告与管理决策输出（补充功能）

**功能**：

- 生成结构化事故报告草案、风险简报和领导驾驶舱摘要。
- 支持 Markdown、PDF、Word 和表格导出。
- 支持“事实字段、风险研判、案例参考、处置建议、待核验事项”分章节输出。
- 支持人工修订痕迹、版本对比、审核意见和最终签发。
- 报告中附带证据索引和模型/知识版本。

**产品定位**：报告生成是管理辅助工具，不是自动签发工具。

---

### F8. 数据、模型与知识治理（补充功能）

#### 数据治理

- 数据集目录、字段字典、质量评分、敏感信息脱敏、版本和血缘。
- 记录原始文件、清洗规则、过滤行数、缺失率和异常率。
- 支持数据集冻结，保证论文实验和线上结果可复现。

#### 模型治理

- 模型注册、训练任务、参数、依赖、指标、解释结果和发布状态。
- 支持开发、测试、生产三个环境。
- 支持模型回滚、灰度使用和效果监测。

#### 知识治理

- 知识草稿、人工审核、发布、废弃。
- 记录来源、置信度、适用范围、有效期和冲突关系。
- 支持阈值规则变更的审批和影响分析。

### F9. 评估与质量监控（补充功能）

#### 模型评估

- 事故模型：Macro-F1、AUC、校准、分组稳定性、数据漂移。
- 极值模型：拟合优度、阈值敏感性、置信区间、稳定性和重现水平。
- 告警：准确率、召回率、误报率、告警提前量、重复率。

#### LLM/报告评估

- 字段准确率、结构完整率、未知项处理率、证据覆盖率。
- 规则一致性、引用正确率、未支持事实率、人工修改量。
- 事实准确性、可追溯性、处置合理性、可读性和实用性人工盲评。

#### 运行监控

- 数据接入延迟、模型任务耗时、图谱检索耗时、LLM 响应时间。
- 错误日志、超时、空结果、知识冲突、异常输出和人工驳回率。

---

### F10. 安全、权限与审计（补充功能）

- 用户、角色、路段数据范围和操作权限。
- 事故数据脱敏和最小化展示。
- 关键操作二次确认：发布阈值、发布知识、关闭事件、签发报告。
- 全量操作日志：谁、何时、查看/修改/发布了什么。
- 证据和报告的访问水印、导出记录和版本锁定。
- LLM 提示词、上下文证据、输出和校验结果留存。

## 7. 关键页面与交互要求

### 7.1 风险事件详情页

页面必须同时展示：

- 事件摘要和当前状态。
- 地图位置和道路场景。
- 事故侧风险因素及 SHAP 贡献。
- 轨迹侧冲突指标及 EVT 阈值。
- 图谱证据路径。
- 相似案例卡片。
- LLM 风险报告。
- 推荐处置方案和执行状态。
- 待核验信息、人工批注和审计记录。

### 7.2 证据卡片

每条风险结论应以证据卡片展示：

```text
结论：夜间条件下事故严重程度风险升高
来源：事故模型 / SHAP
重要性：0.312
适用场景：已发布模型覆盖的事故样本
数据集版本：ACC-2026-01
模型版本：xgb-severity-v0.3
审核状态：已审核
```

### 7.3 处置推荐卡片

```text
措施：增加现场警示并进行车道防护
优先级：P0
触发依据：TDTC 超过高风险阈值 + 历史追尾案例
建议责任角色：现场处置负责人
时限：立即
证据：EVT规则 R-2026-014；案例 CASE-2025-028
状态：待人工确认
```

## 12. 需要优先确认的产品决策

1. 第一版使用离线文件上传，还是接入实时轨迹流？建议先采用离线 + 准实时接口。
2. 第一版服务单一路段还是多个路段？建议先聚焦论文数据覆盖路段，再抽象为多路段。
3. 知识图谱首版采用轻量 JSON/SQLite 还是直接使用图数据库？建议先用可审计的 JSON + 查询层验证流程，再切换图数据库。
4. LLM 是本地部署还是远程 API？建议通过统一模型适配层隔离，优先保证可替换和脱敏。
5. 事故图片是否参与视觉识别？建议第一版仅作为证据资产关联，视觉识别单独立项并加入人工确认。
6. 哪些处置措施可以自动生成工单，哪些必须人工批准？建议 P0/P1 全部人工确认。

## 13. 产品结论

本系统不是单纯的“模型展示平台”，而是一个面向道路管理的风险知识与事件处置平台。论文中的四项核心成果对应四个分析引擎：

- SHAP：回答“事故风险受哪些因素影响”；
- EVT：回答“轨迹冲突何时达到极端风险”；
- 知识图谱：回答“这些因素、阈值、案例和措施如何关联”；
- LLM Agent：回答“当前事件应该如何解释、如何形成处置建议和报告草案”。

补充的地图、告警、工单、审核、版本和评估能力，使研究成果能够进入道路安全管理流程，并保持事实边界、证据可追溯和人工可控。
