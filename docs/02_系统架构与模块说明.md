# 系统架构与模块说明

## 1. 总体架构

```text
┌─────────────────────────────────────────────────────────────┐
│                       展示与管理层                          │
│ 风险驾驶舱 │ SHAP分析 │ EVT分析 │ 图谱分析 │ 事件中心 │ 报告 │
└──────────────────────────┬──────────────────────────────────┘
                           │ API / WebSocket
┌──────────────────────────▼──────────────────────────────────┐
│                       业务服务层                            │
│ 数据服务 │ 分析任务服务 │ 规则引擎 │ 图谱查询 │ 案例检索 │ Agent │
│ 告警服务 │ 事件工单 │ 报告生成 │ 审核服务 │ 评估监控 │ 权限审计 │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                       算法与知识层                          │
│ XGBoost + SHAP │ TDTC/MTTC/PET/ΔV │ POT/GEV/GPD │ LLM适配器 │
│ 风险知识图谱 │ 案例知识库 │ 阈值规则 │ 证据索引 │ 评估集 │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                       数据与基础设施层                      │
│ 事故数据 │ 轨迹数据 │ 道路拓扑 │ 天气数据 │ 图片资产 │ 日志 │
│ 对象存储 │ 关系库 │ 图谱存储 │ 缓存 │ 消息队列 │ 模型仓库 │
└─────────────────────────────────────────────────────────────┘
```

## 2. 模块边界

### 2.1 数据接入与治理模块

负责文件/API 接入、字段映射、质量检查、脱敏、数据版本和血缘。不得在此模块中直接修改业务结论。

### 2.2 事故分析模块

负责训练事故严重程度模型、生成 SHAP 解释、形成知识候选。模型结果需以任务方式运行，记录参数和依赖。

### 2.3 轨迹冲突与极值模块

负责轨迹清洗、车辆交互、冲突指标、POT 抽样、极值拟合、阈值生成和稳定性评估。

### 2.4 知识管理模块

负责实体、关系、规则、案例、证据、审核和版本。图谱是结构化索引层，案例库是叙事内容层。

### 2.5 风险 Agent 模块

采用“工具路由 + 提示词组装 + 输出校验”的结构。LLM 不直接访问原始数据库，只能使用经过权限控制的证据包。

### 2.6 事件与处置模块

负责事件状态、告警、工单、推荐措施、执行记录、复盘和关闭。

## 3. 证据包设计

每次风险研判生成一个不可变证据包：

```json
{
  "incident_id": "INC-2026-0001",
  "structured_facts": [],
  "rule_results": [],
  "graph_evidence": [],
  "case_evidence": [],
  "model_versions": [],
  "knowledge_version": "kg-2026-10-06",
  "prompt_version": "risk-agent-v0.1"
}
```

LLM 输入只允许引用证据包中的内容。报告生成后，保存输入证据包哈希、模型响应、校验结果和人工修改记录。

## 4. 风险等级决策链

```text
规则底线判定 ──┐
模型解释结果 ──┼─> 风险等级合成器 ─> 结构化风险结果 ─> LLM表达
案例和图谱证据 ─┘
```

建议采用：

```text
最终风险等级 = max(规则最低等级, 模型/场景综合等级)
```

其中 `max` 使用业务等级序而非字符串比较。若规则数据缺失或模型不适用，必须降低结论置信度，而不是静默忽略。

## 5. 推荐部署形态

### MVP

- 单体后端 + 异步任务队列。
- 文件对象存储保存原始数据、图表和报告。
- 关系数据库保存业务数据。
- JSON/SQLite 保存初始知识和规则，保留未来迁移图数据库的字段设计。
- LLM 通过统一适配接口调用本地模型或远程服务。

### 生产演进

- 数据接入、分析任务、知识服务、Agent、事件服务拆分。
- 使用消息队列承载轨迹流和异步任务。
- 使用图数据库承载多跳查询。
- 使用模型注册与实验追踪系统保存模型版本。
- 使用集中日志和指标监控服务跟踪任务质量。

## 6. 安全设计

- 原始数据与分析结果分离存储。
- LLM 只接收脱敏后的结构化字段和审核证据。
- 任何自动动作必须经过策略审批和用户确认。
- 将提示词注入、越权查询、未支持事实和规则冲突纳入安全测试。
