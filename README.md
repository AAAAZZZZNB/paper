# 道路管理系统（基于交通风险智能体论文）

> 本目录用于承载“融合事故与冲突先验知识的道路管理系统”产品设计、数据、模型、知识库与后续应用代码。
>
> 当前阶段：产品设计与工程骨架建立（2026-10-06）

## 产品定位

面向道路管理、交通安全、应急处置和科研分析人员，构建一个“数据分析—风险知识—风险推理—处置闭环”的道路安全管理平台。系统以论文中的 **XGBoost-SHAP 事故风险分析、非平稳极值模型（POT/GEV/GPD）轨迹冲突分析、交通风险知识图谱、案例知识库和知识增强大语言模型 Agent** 为核心能力，并补充数据治理、风险地图、告警闭环、报告审核和模型评估等工程化功能。

## 核心能力

1. **事故数据 SHAP 分析**：分析事故严重程度及其影响因素，生成全局/局部 SHAP 图、影响方向、特征排名和可解释结论。
2. **轨迹数据极值风险分析**：基于 TDTC、MTTC、PET、ΔV 等指标，识别高风险冲突，建立 POT/GEV/GPD 非平稳极值模型，输出阈值和风险等级。
3. **交通风险知识图谱分析**：将事故侧 SHAP 知识、轨迹侧 EVT 知识、道路场景、风险等级、历史案例和处置措施统一关联，支持路径分析和证据溯源。
4. **大语言模型风险分析与事故处置推荐**：融合结构化指标、图谱证据、历史案例和阈值规则，形成可审计的风险评估、处置建议和事故报告草案。
5. **道路管理闭环**：补充风险地图、实时/准实时告警、事件工单、处置反馈、模型版本管理和人工审核，避免系统只停留在“展示分析结果”。

## 设计原则

- **风险等级由规则兜底**：当 TDTC、MTTC 等指标触发高风险阈值时，语言模型不得将风险等级降级。
- **证据优先于生成**：任何事故事实、风险结论和处置建议都应标注数据、模型、规则或案例来源。
- **未知信息显式标记**：没有证据支持的内容必须标记为“待核验/未知/可能”，不能补写成已确认事实。
- **人机协同**：系统输出定位为风险研判和事故报告草案，不替代正式事故调查、责任认定和现场指挥。
- **可追溯可复现**：记录数据版本、模型版本、知识版本、阈值版本、提示词版本和操作日志。
